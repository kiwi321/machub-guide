开始之前

准备两台 Mac

  • 你的 Mac 和 hub 都装好 Tailscale，登录同一个账号。
  • hub 保持开机，不要睡眠。hub 睡眠时挂载会断，醒来后 MacHub 会自动重新挂载。
  • 知道 hub 上一个账户的账户名和登录密码。下面的设置都对这个账户做。

第 1 步 · 在 hub 上

设置 hub

只做一次。hub 上不用装 MacHub。

  1. 打开 系统设置›通用›共享，打开「文件共享」，点它旁边的 ⓘ。

    共享文件夹里加上放项目的文件夹，一般是家目录里的 Projects，名字只能用英文字母、数字和 . _ -。用户里只给自己「读与写」，「所有人」设成「无访问权限」。

  2. 在同一个窗口点「选项…」，在「Windows 文件共享」里勾上自己的账户，输入登录密码。

    通过 Tailscale 挂载时，两台 Mac 之间用不了 Kerberos，要靠这个验证密码。不勾的话，挂载会报用户名或密码不对。

  3. 打开「远程登录」，点 ⓘ，在「仅这些用户」里加上自己。

    这里会显示一行 ssh 账户名@地址。记下账户名，连接时要填。

第 2 步 · 在你的 Mac 上

安装 MacHub

  1. 下载 MacHub.zip：GitHub 上的最新版本。

    仓库是私有的，要有权限才能打开。打不开就向发给你这个页面的人要安装包。

  2. 解压，把 MacHub 拖进「应用程序」。

  3. 第一次打开会被系统拦下，因为它没有开发者签名。

    打开 系统设置›隐私与安全性，拉到下面点「仍要打开」。

MacHub 平时只在菜单栏，图标是一个硬盘。点它，再点「打开 MacHub…」就是主窗口。

第 3 步 · 在你的 Mac 上

连接 hub

  1. 打开 MacHub，在「选 hub」列表里点 hub。

    列表来自 Tailscale。hub 不在里面就手动填地址，比如 mac-studio.tailxxxx.ts.net。

  2. 填 hub 上的账户名和登录密码，点「连接」。

    账户名是家目录文件夹的名字，不是锁屏上显示的全名。「共享文件夹」默认是 Projects，和第 1 步共享的文件夹一致就行。

点「连接」后，MacHub 会：

  • 生成一把专用的 SSH 密钥并装到 hub，以后 ssh hub 不用输密码
  • 把 hub 的 ~/Projects 挂到 ~/remote/projects，断了会自动重新挂载
  • 把 hub 的用法写进 ~/remote/hub.md
  • 把密码存进这台 Mac 的钥匙串，只用来重新挂载

日常使用

在 hub 的项目里用 AI

打开项目

启动命令就是进到项目目录，再照常启动 AI：

cd ~/remote/projects/my-app && claude
cd ~/remote/projects/my-app && codex
cd ~/remote/projects/my-app && grok

在 MacHub 窗口里点「选择文件夹…」选一个项目，会列出这几条命令，路径换成你选的文件夹。每条都能复制到自己的终端里运行，也可以点「运行」，MacHub 会打开「终端」执行同一条命令。菜单栏里的「用 Claude 打开文件夹…」等，会先让你选文件夹，再直接启动。

让 AI 用 hub

AI 默认不知道有 hub。需要它在 hub 上装依赖、跑构建和测试、启动服务时，跟它说一句：

hub 的用法见 ~/remote/hub.md

它读完就知道项目在 hub 上的哪个目录，以及怎么用 ssh hub '…' 在 hub 上执行命令。哪些命令放到 hub 上跑，由它自己判断。你自己也可以用 ssh hub 登录 hub。

在 hub 上跑长任务

构建、测试、训练这类要跑很久的命令，可以放到 hub 的 tmux 里后台运行，ssh 断开也不会停：

cd ~/remote/projects/my-app
~/remote/bin/hub-run build 'npm ci && npm run build'
~/remote/bin/hub-wait build   # 等它结束，返回它的退出码

另外还有 hub-log（看日志，-f 跟到结束）、hub-jobs（列出任务）、hub-stop（停止）。命令用 hub 的登录 shell 执行，默认在当前项目对应的 hub 目录里运行。这些用法也写在 hub.md 里，AI 读了就会用。hub 上要装有 tmux。

遇到问题

常见问题

列表里没有 hub
两台 Mac 要登录同一个 Tailscale 账号，hub 要在线。也可以直接在下面填 hub 的地址。
提示「账户名不能有空格」
填成了锁屏上显示的全名。到 hub 的「远程登录」ⓘ 里看 ssh 账户名@地址，填 @ 前面那段。
挂载失败，说用户名或密码不对
在 hub 的「文件共享」ⓘ →「选项…」里勾上「Windows 文件共享」，再回来连接。如果是这个原因，MacHub 会直接告诉你。
ssh hub '…' 找不到 node、npm
这种 ssh 不读 hub 的 ~/.zprofile，找不到 Homebrew 装的命令。MacHub 窗口里这一项打叉时点「修复」，它会在 hub 的 ~/.zshenv 里加一段带标记的设置，只对这种 ssh 生效，不影响 hub 上的终端。
菜单栏图标变成感叹号，或者 ~/remote/projects 是空的
挂载断了，一般是 hub 关机、睡眠或 Tailscale 掉线。MacHub 每分钟检查一次，会自动重新挂载；也可以点「重新挂载」。
系统问 MacHub 能不能使用钥匙串
点「始终允许」。更新 MacHub 后，第一次读取密码时会问一次。
Codex 每次执行 ssh hub 都要批准

Codex 默认的沙箱不让联网。在 ~/.codex/config.toml 里加上：

[sandbox_workspace_write]
network_access = true
怎么更新 MacHub
MacHub 启动时和之后每 6 小时检查一次新版本。有新版时，菜单栏最上面会出现「更新到 vX 并重启」，点一下就会下载、替换、重新打开。下载要用这台 Mac 上已经登录的 GitHub 命令行工具 gh（brew install gh，再 gh auth login），账号要能看到这个仓库。没装 gh 时，「检查更新」会打开 GitHub 下载页。更新后系统可能再问一次能不能访问网络宗卷和钥匙串，点「允许」。
不用了，怎么断开
MacHub 窗口最下面点「断开 hub…」。它会卸载 ~/remote/projects，删掉钥匙串里的密码和 ~/remote/hub.md。hub 上的文件不受影响。
